## The permission pre-flight is part of intake, not an afterthought

A card is the driver's whole reading list, so if the card does not name the
exact command strings, the driver invents a spelling and the owner pays a
click for it.

For every card you write:

1. **Fill `## Commands this card needs` with literal strings**, copied out of
   `docs/command-forms.md` and the machine table for the card's machine
   (`docs/command-forms-windows.md` / `-mac.md`; the allowed-command tables).
   Not "run the suite":
   the absolute interpreter and its arguments. Not "commit the work":
   `git -C <absolute path> commit -m "<one line>" -- <path>`.
2. **Set `triggers:` in the frontmatter**, which is the category the owner
   scans:
   - `none` , every command is allowlisted. Safe unattended.
   - `known` , one or more commands WILL prompt. Name them and say what
     stalls. Raise them in ONE form before the card goes into an unattended
     lane.
   - `denied` , a command is in the deny list (any remote write). The card is
     broken: re-plan the step or hand it back.
3. **Check each string against `settings.json` allow AND deny yourself.** The
   table is generated by hand, so it can lag; settings.json is the truth. If
   the table is missing a form the card needs, that is a finding for
   `/fast-lane`: **write one line in `reports/personas/fast-lane/INBOX.md`**,
   and the card says so too. Never edit the permission list yourself, and
   never spawn a Fast Lane; the quarterback is the only persona that may.
4. **Never write a `cd`-based, relative, variable-path, chained, or
   multi-line command into a card.** The lint flags several of these and
   `hooks/shell-form-guard.*` blocks the rest at runtime, so a card carrying
   one is a card that cannot be worked as written.

A `plan-first` card still gets the pre-flight: the plan is approved with the
commands already known, not discovered mid-implementation.

## Wrap-up

Write one line into `reports/personas/intake/turns.md` (format in
`reports/personas/README.md`): which cards you cut, their `triggers:`
category, and any permission gap you raised or could not close. That file is
the quarterback's context, not the owner's reading; the card itself stays the
record.
